# Abacus Experts — website

A Next.js (App Router) + Tailwind CSS v4 site containing both landing pages:

| Route | Page | Source it was ported from |
| --- | --- | --- |
| `/` | Home — overview, programmes, how it works | new |
| `/abacus-online-classes` | Abacus **online** classes (all regions / national) | `abacus-2.html` |
| `/abacus-classes-in-hyderabad` | Abacus classes in **Hyderabad** (one region) | `abacus-1.html` |

The pages cross-link (header nav + footer), share one design system, and share
all chrome/logic through reusable components. The header's **Classes** dropdown
and the footer class links are generated from `lib/nav.js`, so the two class
routes are defined in exactly one place.

## Before launch — one required step

Open **`lib/business.js`** and fill in your verified details **once**:

```js
export const BUSINESS = {
  name: "Abacus Experts",
  url: "https://abacusexperts.com",   // production origin, no trailing slash
  phoneDisplay: "+91 …",
  phoneDigits: "9198…",      // digits only, incl. country code
  whatsappDigits: "9198…",   // digits only, incl. country code
  email: "hello@abacusexperts.in",
};
```

Until `whatsappDigits` is set, the lead form and WhatsApp buttons show a
"number not configured yet" notice instead of opening WhatsApp. This is the only
place these values live — every page reads from it.

`BUSINESS.url` is already set to the production domain. It feeds `metadataBase`
in `app/layout.js`, so each page declares only a site-relative canonical
(`alternates: { canonical: "/abacus-online-classes" }`) and Next resolves it to
an absolute URL. It also builds the schema.org `@id` values, which are absolute
so all three pages reference one Organization node instead of three. Change the
domain in that one place and everything follows — including `/sitemap.xml`
and `/robots.txt`, which are generated by `app/sitemap.js` and `app/robots.js`.

One thing the code cannot do for you: make sure `www.abacusexperts.com`
**301-redirects** to the bare domain at your DNS/host layer. Every canonical,
`og:url` and sitemap `<loc>` points at `https://abacusexperts.com`, so serving
the same pages on `www.` without a redirect splits crawl signals.

## Develop / build

```bash
npm run dev      # local dev at http://localhost:3000
npm run build    # production build
npm run start    # serve the production build
```

## Structure

```
app/
  layout.js                         # <html>/<body>, fonts, global metadata
  globals.css                       # Tailwind + brand tokens (@theme) + base layer
  page.js                           # home
  abacus-online-classes/page.js
  abacus-classes-in-hyderabad/page.js
  sitemap.js                        # /sitemap.xml, routes read from lib/nav.js
  robots.js                         # /robots.txt, points at the sitemap
components/                         # Header, Footer, LeadForm, Programme, Faq, Button, …
lib/business.js                     # site URL, phone/WhatsApp config, tracking
lib/nav.js                          # class routes + the header "Classes" dropdown
lib/seo.js                          # shared openGraph block for page metadata
```

Page metadata merges *shallowly* in Next.js: a page that defines `openGraph`
replaces the layout's entirely. `pageOpenGraph()` in `lib/seo.js` exists so
`type` / `locale` / `siteName` are not silently dropped — use it rather than
writing a bare `openGraph` object in a page.

Base element styles in `globals.css` live inside `@layer base`. Keep them there:
unlayered CSS outranks Tailwind utilities, which would make `text-white` on a
heading silently lose to the base `color`.

Brand colours, radii, shadow, fonts and the responsive breakpoints are defined
once in the `@theme` block of `app/globals.css` and used as Tailwind utilities
(`bg-navy`, `text-slate`, `rounded-xl2`, `shadow-card`, `max-lg2:`, `max-sm2:` …).

> The original `abacus-1.html` / `abacus-2.html` files (in your Pictures folder)
> are left untouched as reference.

## Docker

`next.config.mjs` sets `output: "standalone"`, so the image ships only the traced
`node_modules` and a minimal `server.js` — no dev dependencies.

```bash
docker compose up -d --build     # build and run at http://localhost:3020
docker compose logs -f web
docker compose down
```

Or without compose:

```bash
docker build -t abacus-experts .
docker run -d --name abacus-experts -p 3020:3020 abacus-experts
```

The container listens on **3020** (`PORT` / `HOSTNAME` env vars), runs as the
non-root `node` user, and has a healthcheck that requests `/`. To publish on a
different host port, change only the left-hand side of the compose `ports`
mapping, e.g. `"8080:3020"`.

## Deploying as plain static files (optional)

Replace `output: "standalone"` with `output: "export"` in `next.config.mjs` and
run `npm run build`; the static site is emitted to `out/` for hosting on any
static host. (The Docker setup above expects `"standalone"`.)
